# 数据隐私与后端处理说明

本文记录当前试点分支的实际数据流和已实现保护措施，不构成法律意见或学校审批结论。

## 数据在哪里

| 数据 | 本地运行 | 使用远端数据库与 Supabase Storage |
| --- | --- | --- |
| 教师账号、班级画像、教案、课堂反馈、分析结论 | `backend/data/zhiban.db` | 配置的 PostgreSQL 数据库 |
| 录音、参考音源等文件 | `backend/data/uploads/` | 私有 Storage bucket；数据库保存私有对象引用 |
| 远端文件的处理副本 | 不适用 | 后端临时目录中的下载缓存，过期 7 天后启动时清理 |
| API 密钥 | `backend/.env` | 只保存在后端环境变量中 |

Supabase Storage 使用私有桶；服务密钥仅由后端读取。音频流仍经过需要登录且按教师归属校验的 API，不返回公开对象链接。SQLite 模式下，录音随分析记录保存在本机磁盘。

## 发送给外部服务的内容

- 教案生成使用歌曲信息、班级整体教学特征、课堂设备选择和“本课要求”。班级名称、自由填写的群体问题和“教师教学感受”会从发给模型服务的请求中移除；生成后的群体任务仍保留在教案内容里。教师教学感受仍保存在本应用的班级档案里。
- 课堂整体分析在本机/后端提取声学指标后，只把歌曲与年级等课程信息、分段时间、汇总指标和教学目标发送给已配置的模型服务整理建议；不把原始音频文件发送给文本模型。
- 教师自由填写的“本课要求”会发送给所配置的模型服务。不要在其中填写学生姓名、联系方式、健康信息或能识别某个学生的细节。
- API 密钥、邮箱 SMTP 密码和 Supabase 服务密钥不得放进前端或提交到仓库。

音频分析页面要求教师确认已按学校流程完成录音告知与授权，并将确认时间与提示版本写入分析记录。该操作只是应用内留痕，不替代学校、监护人或其他相关方要求的同意流程。

## 上传与临时数据

- 录音与参考音频支持 WAV、MP3、M4A、MP4、AAC、FLAC、OGG、OGA、OPUS、WEBM、WMA、AIF 和 AIFF；单个文件默认最多 100 MB。可通过后端 `AUDIO_MAX_UPLOAD_BYTES` 调整。反向代理仍应配置请求体上限。
- 服务端以随机名称保存上传内容，并在分析记录中使用“课堂录音”“参考音源”等通用显示名，不持久化用户选择的原文件名。
- 后台分析任务处理期间会短暂保存输入文件路径；任务完成、失败或取消后会清空任务载荷。远端存储模式的临时上传副本会在任务结束后删除；SQLite 模式保留作为分析附件的音频，直到教师删除该分析记录。
- 若远端对象已上传但后续分析或数据库提交失败，服务会尝试删除尚未关联记录的对象；删除失败会记入不含文件名和对象地址的后端日志。
- 服务启动时，超过 24 小时仍未结束的任务会标记为中断并清理上传目录中的临时文件；新近任务不会被另一运行实例误清理。
- 远端对象下载缓存最多保留 7 天后由服务启动时清除；缓存删除不影响 Supabase 中的正式文件。
- 邮箱验证码有效期 10 分钟；已使用或过期验证码、过期登录会话会在服务启动时清理。同一邮箱每分钟最多请求一次、每小时最多请求五次验证码。

## API 与访问保护

- 业务数据按教师账号归属查询；音频播放、详情和删除都验证当前教师权限。
- 写请求带有 `Origin` 时，后端只接受配置的前端 origin 或当前同源请求；不受信任的跨站写请求会返回 403。
- `/api/` 响应设置为 `private, no-store`，避免共享缓存保存账号或课堂记录。
- 生产环境需将 `ALLOWED_ORIGINS` 设置为实际前端 origin；`APP_ENV=production` 时后端强制启用 Secure Cookie。不要将带真实密钥的 `.env` 上传到 GitHub。

## 保留、查看和删除

教师可以在教学档案中查看自己的音频分析记录，并删除单条音频分析；删除分析时应用同时尝试删除其音频附件和远端对象。若删除远端对象失败，后端会返回错误，需检查存储配置后重试。

班级画像、教案、课堂反馈和未删除的音频分析没有自动到期清除。数据库备份的保存期限由运行者管理。当前版本还没有教师自助的完整账号导出/账号注销流程，也没有跨多个后端实例共享的登录失败限流；启用公开服务前应完成这些运营和安全控制，并明确学校的数据保存期限与删除责任。

## 试点验收建议

1. 在本地与远端存储配置下各上传一份小于上限的录音，并确认结果可回放。
2. 上传不支持的扩展名、空文件和超限文件，确认分别返回明确错误且没有留下部分文件。
3. 完成、失败、取消后台任务后检查 `audio_analysis_jobs.request_json` 已为空；确认远端模式临时上传副本被删除，而已保存的私有 Storage 文件仍能回放。
4. 使用允许与不允许的 `Origin` 发起写请求，分别确认成功与 403。
5. 删除一条音频记录，确认数据库关联和私有 Storage 对象均已清理。
