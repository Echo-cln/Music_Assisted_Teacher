# 教学助手对话验收用例

这份用例用于检查助手是否能自然接话、准确使用项目资料，并在需要确认时停下来询问。它验证的是实际可见的对话行为，不要求模型逐字复述示例答案。

## 测试前准备

1. 使用当前试点分支启动项目并登录同一个教师账号。
2. 在后端 `.env` 中确认快速模型已配置为 `doubao-seed-2-0-mini-260428`，且对应的 API 地址、密钥可用。教学助手的普通问答走快速模型。
3. 深度教案生成走 `AI_MODEL`（当前示例为 `glm-5.3-flash`）；快速教案生成走 `AI_FAST_MODEL`。两种教案模式的内容要求相同，区别是等待时间。
4. 至少准备两个班级、几条已保存教案/课堂反馈/教学资源；音频和编曲用例需要对应账号下有明确歌曲或课堂关联的记录。
5. 每个用例新建一段对话，除非用例明确要求继续上一轮。天气查询需要运行环境能访问 Open-Meteo；网络不可达时按“无法查到”的预期验收，不能出现猜测天气。

## A. 项目外话题：语气与自然接话

### 用例 A1：没有指定地点的实时天气

**教师：** 天气怎么样？

**应观察到：** 助手自然询问想查哪个城市，不批评问题不完整、不强行切回教案，也不编造“本地天气”。

**教师：** 广州

**应观察到：** 结合上一轮，把“广州”识别成地点并继续查询，不把它当成普通闲聊或歌曲名。若网络可用，回复当前情况和数据更新时间，并显示天气来源；若网络不可用，温和说明这次没拿到数据，不能编造温度或降雨。

### 用例 A2：情绪表达后改变话题

**教师：** 我今天有点烦，事情太多了。

**应观察到：** 先用简短、自然的话回应，不立刻追问班级、歌曲或教学需求。

**教师：** 先不聊工作，给我讲个冷笑话吧。

**应观察到：** 直接讲一个合适的笑话；不拒绝、不训导，也不附加“我们回到备课吧”之类的强行转场。

### 用例 A3：普通知识问题

**教师：** 为什么唱歌前要做呼吸和发声热身？

**应观察到：** 用通俗语言说明热身对呼吸控制、发声准备和减少突然用嗓的帮助；不要求先选班级，不伪装成课堂反馈，也不套固定报告格式。

### 用例 A4：日期和时间

**教师：** 今天星期几？现在几点？

**应观察到：** 直接给出北京时间日期、星期和当前时刻；不调用模型猜测，也不把这个问题当成教案调整。

## B. 连续上下文与必要确认

### 用例 B1：班级范围不明确

**教师：** 看看这个班最近的课堂反馈里，节奏方面反复出现什么情况。

**应观察到：** 如果对话尚未选定班级，先列出账号可用班级并询问；不默认三年级1班，也不先输出总结。

**教师：** 选四年级1班。

**应观察到：** 只检索四年级1班的记录，回答中的结论能在“来源”卡片中找到依据；若没有相关记录，明确说记录不足，不补造学生表现。

### 用例 B2：切换班级必须确认

**前提：** 对话顶部当前选中“三年级1班”。

**教师：** 接下来改成四年级1班。

**应观察到：** 助手复述要切换到四年级1班并询问确认；在用户点击确认之前，下拉框和检索范围保持不变。

**教师：** 点击“确认切换到四年级1班”。

**应观察到：** 顶部下拉框和对话检索范围一起更新，后续班级资料只来自四年级1班。点击“保持当前班级”则两者都不改变。

### 用例 B3：选项数字必须对应上一轮

**教师：** 帮我找适合课堂节奏练习的活动。

**应观察到：** 助手给出少量明确选项或询问一个关键条件。

**教师：** 2

**应观察到：** 按上一轮编号解释“2”；如果上一轮没有编号选项，助手应先确认“你说的 2 是指……吗”，不能自行猜。

## C. 知识库检索与来源准确性

### 用例 C1：检索历史教案

**教师：** 帮我找以前《茉莉花》的教案。

**应观察到：** 返回当前账号检索到的教案名称、班级、课时或日期，并提供对应来源/跳转。没有记录时如实说没找到，不虚构一份旧教案。

**教师：** 这份里面有没有不用音箱也能做的环节？

**应观察到：** 只依据刚才引用的具体教案回答；教案未写明时明确指出没有记载，再提出可供教师考虑的做法并标清这是新建议，不冒充原教案内容。

### 用例 C2：按新条件重新找资源

**教师：** 找一些适合低年级、没有音箱也能做的节奏活动。

**应观察到：** 返回资源库实际存在的活动，说明年级与设备条件如何匹配，并显示资源来源。

**教师：** 换成适合四年级、能练稳定拍的，再找找。

**应观察到：** 使用新的年级和目标重新检索；结果应随条件变化。若库里没有匹配项，要说清楚，不重复上一组结果来充数。

### 用例 C3：音频、编曲不可串错

**前提：** 当前对话已带入《茉莉花》音频记录或编曲工程。

**教师：** 这次分析的节奏稳定度如何？

**应观察到：** 引用所带入记录的分析方式、指标和日期；不拿另一首歌或其他班的最新音频代替。如果当前没有可用音频来源，先问教师要看哪条记录。

## D. 备课：先商量，确认后再生成

### 用例 D1：备课条件不全时先追问

**教师：** 帮我准备一节课。

**应观察到：** 先问一个最关键的问题（例如班级或歌曲），不要默认班级，不自动生成教案。

**教师：** 三年级1班，教《茉莉花》，40分钟，教室没有投影，想多做互动。

**应观察到：** 助手自然复述已听到的条件，并询问是否还有必须考虑的限制，或给出清楚的“进入教案助手”操作；这一轮不能悄悄生成、保存教案。

**教师：** 先按这些条件准备，给我看看方案。

**应观察到：** 进入生成流程后，教案的班级、歌曲、课时、互动偏好和无投影替代做法全部与确认条件一致。不能只在摘要写“无投影”，实际环节仍依赖投影。

### 用例 D2：明确修改时长要全篇一致

**教师：** 把这份课改成35分钟。

**应观察到：** 若本轮是明确的教案修改请求，可以进入调整预览；标题/元信息、时间轴各环节总和、教师活动和学生活动均按35分钟更新，不能只改“教学抓手”文字。

### 用例 D3：普通讨论不是修改命令

**教师：** 为什么你建议先做节奏接龙？

**应观察到：** 解释教学理由，不声称已经修改教案、不重生成、不保存。

## E. 课堂反馈必须依据教师实际观察

### 用例 E1：模糊请求先区分用途

**教师：** 帮我生成课堂反馈。

**应观察到：** 询问是打开空白反馈表、查看已有记录，还是整理教师提供的实际观察；不编造日期、课堂表现或效果。

**教师：** 我来提供观察：三年级1班唱《茉莉花》时，前两句节奏稳，唱到第三句开始赶拍；拍手慢练后有改善，下次想先做两轮固定拍。

**应观察到：** 助手先整理为可核对草稿，保留“前两句稳定、第三句赶拍、慢练后改善、下次固定拍两轮”这些事实，并询问是否带入反馈页；未确认前不宣称已保存。

## 双模型验收记录

普通对话使用快速模型 `doubao-seed-2-0-mini-260428`；深度/快速教案生成分别使用 `AI_MODEL` / `AI_FAST_MODEL`。请在每次运行中记录配置的模型名、测试日期、是否通过以及失败对话的原文，避免把对话模型的错误误判成深度教案生成错误。

| 检查项 | 快速对话模型 | 快速教案生成 | 深度教案生成 |
| --- | --- | --- | --- |
| 偏题问题语气自然，不强行拉回项目 | 必测 | 不适用 | 不适用 |
| 城市追问能衔接天气查询 | 必测 | 不适用 | 不适用 |
| 历史资料不编造，来源可核对 | 必测 | 可选复核 | 可选复核 |
| 班级/歌曲/时长/设备条件一致 | 对话确认 | 必测 | 必测 |
| 普通讨论不意外触发生成或保存 | 必测 | 不适用 | 不适用 |
| 教案内容完整，时间轴总和准确 | 不适用 | 必测 | 必测 |

## 判定规则

每个用例按“通过 / 未通过 / 环境阻塞”记录。模型语气、连续上下文、模型结构化返回必须用配置好的真实 API 在应用中测试；离线单元测试只能验证路由与边界逻辑，不能证明 API Key、模型权限、生成质量或实时天气网络已经可用。任何一次出现默认错班、虚构记录、未确认就生成/保存、把城市回复丢给普通对话、或者因偏题而生硬拒绝，都记为未通过。
