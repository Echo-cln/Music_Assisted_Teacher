# 数字乐器与智能编曲工作台验收清单

本清单区分代码能力、外部依赖和目标电脑实测结果。未在目标设备操作过的项目不标记为“实测通过”。

## 一、和弦与主题

工作台输入旋律、设置 BPM 后，分别生成多轨编曲。测试旋律：

| 测试旋律（每四个音一小节） | 验收重点 |
| --- | --- |
| `C4 E4 G4 E4 A4 C5 E5 C5 F4 A4 C5 A4 G4 B4 D5 B4 C4 E4 G4 C5` | 检查调性、和弦是否随旋律改变 |
| `G4 B4 D5 G5 C5 E5 D5 G5` | 检查 G 调和弦时间轴 |
| `A4 C5 E5 A5 D5 F5 E5 A5` | 检查 A 小调时间轴 |

同一旋律的和弦可以相同；不同风格应体现为配器、节奏密度、音符起点和时值差异。只有耳听并核对 MIDI 时间轴都符合预期后才算通过。

## 二、音色包与本地保存

- 选择授权的 SF2，确认显示名称、Preset、绑定乐器和文件大小。
- 修改包名称及乐器绑定，刷新页面后确认 IndexedDB 中仍存在。
- 使用音区测试和完整旋律试听分别试听；试听音符应来自当前工程，音色由选择的 SF2 或内置采样提供。
- 删除音色包后确认工程仍保留，但对应音色状态能说明需要重新绑定。
- 仓库不提供第三方音色包。请单独核验音源的使用与再分发许可。

## 三、乐谱导入

MusicXML/MIDI 可以直接导入；图片或 PDF 识谱依赖运行后端的电脑上安装 Audiveris 和 OCR 语言包。

1. 用单页、清晰、正向的 PNG/JPG/PDF 导入。
2. 检查上传进度从开始到结束、成功或失败状态，以及卷帘和谱面音符。
3. 人工核对音高、调号、时值、连线、附点和多声部。
4. 故意使用模糊图片，确认失败提示可读且不会显示“已成功”。

Audiveris 属于 AGPL-3.0 的外部程序；项目不会打包其二进制文件。识谱结果需要人工核对。

## 四、音频验证

- 课堂整体分析：用带课堂环境声的录音，确认结果呈现分段声学证据，并说明它不是个人成绩。
- 单人练唱：用清晰独唱参考与同旋律练唱录音，核对对齐和逐音偏差。
- 混音参考：未安装 Demucs 或分离失败时，应明确不可评分，不应显示伪造的零分。
- 无参考旋律：应只显示课堂整体分析线索，不得宣称判断音准正确与否。

## 五、教案到课后反馈

1. 选设备条件（电脑/音箱、手机/音箱、投影，或无电子设备），生成教案。
2. 检查每个流程环节包含教师动作、学生任务、观察依据和低设备替代活动。
3. 点击“进入授课视图”，逐环节切换、启动/暂停计时并退出；退出后普通预览内容仍完整。
4. Word/PDF 导出后检查课堂设备、目标观察依据、流程观察点和替代活动是否保留。
5. 保存课堂反馈，为每个目标选择状态；刷新并打开反馈档案，确认观察状态可回看。

## 六、尚需教师实测

- 不同设备条件下生成内容的实际可行性；
- 授课视图在目标电脑和投影比例下的可读性；
- 课堂目标观察是否和实际学生表现对应；
- 课堂声学线索与音乐教师听辨的一致程度；
- 浏览器采样加载、SF2 兼容性和 Audiveris OCR 环境。

仅通过静态检查不能代替这些现场验收。
